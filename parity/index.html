4-bit ALU Encrypt: light vs silicon The idea

Eight bits, one pass of light

The full adder's light-only cascade failed: interference XORs that switch beams on and off cannot feed one another. This chip encodes each bit as a phase instead, 0 or π, on one beam. Phases add, so eight sections in a row compute b1 XOR b2 XOR … XOR b8, the parity, with no detector in between. Click the sections: the levels are from the simulated light of the drawn chip.

Why this cascades and the full adder did not

Bits as beams on and off (the full adder)

An XOR made by switching beams leaves "only A" and "only B" with nearly opposite phase. Both mean 1, but they are different light. A second XOR that adds the carry-in beam can cancel one of them and doubles the other: in the best case it still leaves 1.9× a full "1" of light where there should be darkness. So the full adder detects XOR 1 and re-applies it electronically.

Bits as phase on one beam (this chip)

Here every 1 flips the phase of the same light by π. Whatever came before, the light is still at 0 or π: it is itself a valid bit for the next section. Only the very end turns phase into brightness, against the reference arm. The cascade that failed with beams works with phase.

What it costs: the errors add up too

Nothing between the sections restores the signal. If a section's drive gives π plus a small error, the next section adds its own error on top. Calibration on this chip leaves well under 1° per section; a fast modulator's swing drifts and has to be trimmed. Set the error and the length of the chain.

How fast: eight live bit streams

Time-domain simulation of the drawn circuit with eight independent random bit streams, one per section, read straight off the PARITY output. Light reaches section 8 about 15 ps after section 1, so each input's electrical line is made that much longer (aligned). The sections are treated as fast phase modulators placed where the heaters are.

The chip

Drawn in KLayout with the SiEPIC EBeam process design kit (Applied Nanotools): 220 nm silicon waveguides and titanium-tungsten heaters. On this process the sections are heaters, slow but enough to test the logic on a real die.

What is real here

The layout passes the foundry's checks. The light levels come from a circuit simulation of the extracted layout with the design kit's component models, at nine process corners, with heater-to-heater spread, crosstalk and a random arm offset on every simulated die, calibrated using only the grating-coupler reading. The speed runs use the same circuit in the time domain. The electronic latency is a lower-bound model. Nothing is fabricated yet.

What it is good for

Parity is the simplest error check: one extra bit that says whether a word has an odd number of 1s, and the building block of checksums and CRCs. Here it is computed on data that is already light, in one pass. The larger point is the encoding: phase lets interference logic chain stages without going back to electronics, which the beam-switching gates of the paper cannot do.

What it does not solve

  • No gain: errors add along the chain, so each drive must be trimmed to about 1–2%.
  • Real fast modulators are millimetres long, not 120 µm, so lining the inputs up in time is a real design job.
  • The inputs start as electrical signals. An electronic XOR tree is only three gates deep; the gain is only for data that is already a fast optical stream.
